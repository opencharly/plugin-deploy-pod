# 2026.330.2327 — fix(pod): bind the SONAME symlink as the CDI library source

## Summary

`sonameBinds` computed the host SONAME symlink that resolves to the mounted versioned library, then
emitted the **versioned file** as the bind source and the symlink's name as the container target, so
a unit carried:

```
Volume=/usr/lib/libcuda.so.615.78.08:/usr/lib/libcuda.so.1:ro
```

A driver upgrade replaces that versioned target and removes the old versioned path, so the unit then
fails with "no such file or directory" until it is regenerated. The fix binds the **host symlink
itself** as the source (`/usr/lib/libcuda.so.1`), keeping the same container target — the symlinks
survive the upgrade.

Head: `d9b55cb6d3ebb113b9bd251629699e037f76c304`
Diff: 2 files changed, 16 insertions(+), 9 deletions(-)

- `candy/plugin-deploy-pod/cdi_spec.go` — `HostPath` is now the symlink; the doc comment says why. A
  drive-by: `mountIsReadOnly`'s three-line loop became `slices.Contains` (the linter's
  `slicescontains` hint, one line, same behaviour).
- `candy/plugin-deploy-pod/cdi_spec_test.go` — the test now asserts the **SOURCE** of every `*.so.1`
  bind, which is what let a version-pinned source pass before.
