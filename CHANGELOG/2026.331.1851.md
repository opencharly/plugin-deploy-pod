## Summary

Three parts, one cutover on the rebuild path — and the first two only exist because proving the guard
fix turned up a real gap.

**1. The reviewer's note on `#108`** ("the `if loadErr == nil { loadErr = uerr }` inside an
already-`loadErr == nil` branch is a redundant guard"): the inner test cannot fire, so the loader's
result is assigned directly.

**2. The steady state was not covered.** `#108` resolved a rebuild's box from a declared **bare**
recorded image name, then from the deploy key. Measured on a disposable deploy after one successful
build/config, the entry records a **qualified ref** — `localhost/overlay-base:2026.331.1816` — so
neither candidate matched and the rebuild refused a deploy that has a perfectly good box:

```
charly update pod-overlay-builder --build  → no box to rebuild — the deploy records the image
"localhost/overlay-base:2026.331.1816" … so NOTHING WAS BUILT
```

The IMAGE says which box built it: the `ai.opencharly.box` label — the capability contract's own mapping,
and what `charly box labels <ref> --format ai.opencharly.box` answers. The resolution now asks the image
rather than parsing the ref (a locally re-implemented strip-registry/tag rule would duplicate
`deploykit`'s). Candidates, in order: the bare declared name → the image's box label → the deploy key's
base; a refusal names all three and says NOTHING WAS BUILT.

**3. The path had no bed.** `check-pod-rebuild-build` (new, `disposable: true`, `host: local`) drives both
answers a rebuild can give. **Each arm fails on the pre-`#108` tree, which returned `rc=0` with no build
line for both**:

- a deploy that names no declared box **REFUSES** (`rc!=0`) saying NOTHING WAS BUILT;
- a deploy whose image label names a declared box **actually BUILDS** it
  (`--- Building overlay-base ---`), whatever the later check leg does.
