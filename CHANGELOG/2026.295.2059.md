# 2026.295.2059 — fix(pod): preserve bare env entries on the engine launch path (#38)

## Summary

Fixes the **blocking regression #37 introduced** (`opencharly/plugin-deploy-pod#38`): on the
engine launch path, a **bare `KEY` env entry** (inherit-from-host) was **silently dropped**.

`EngineStartPlanRequest.Env` is a `KEY→VALUE` map, and `envSliceToStrMap` kept only entries
containing `=`. A pre-fix `-e FOO` therefore reached the engine **zero times**, the container
started without the variable, and nothing failed. The systemd-unit path already refused a bare
entry; the direct path dropped it silently.

### What changed (every item in the diff)

- **`engine_ops.go` — the mechanism, not the symptom.** `envArgs` renders every env entry as
  `-e <entry>` **verbatim**, one shape for bare `KEY` and `KEY=VALUE`, and it is passed through
  the request's own `ExtraArgs` channel (appended after env-files, before the image, so
  precedence matches the old map emission). The request's `Env` map cannot express an inherit
  entry, so it is no longer used by this consumer. `envSliceToStrMap` is **deleted**. The
  unreachable `privilege_prefix` application is removed (every rootful engine that declares a
  prefix is refused by `rootfulUnsupported`); its doc comment now states the rootless fact.
- **`config_setup_helpers.go` (`runHook`), `resolve_f12.go` (`charly cmd`, `charly run`,
  `charly exec`)** — the four sibling `-e` loops are collapsed into the one `envArgs` renderer
  (R2). Their emitted argv is unchanged; there is now ONE env-flag implementation in the module.
- **`lifecycle.go`** — the direct-deploy marker starts through **`plan.EngineBin`** (the
  resolved engine) instead of a hard-coded `podman start`, and fails loudly when the plan
  carries no engine binary. This is the R3 residue #38 records.
- **`resolve.go`, `resolve_f12.go`** — the sibling comments that still described the podman-only
  shape are corrected (R1 claim-keyed sweep).
- **`engine_ops_test.go`** — the table-driven env guard and the engine-keyed direct-deploy
  start pin.
