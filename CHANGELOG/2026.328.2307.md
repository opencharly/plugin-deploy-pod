# 2026.328.2307 — feat(gpu)!: a CDI device rides a keep-id unit via a derived devices-only spec

## Summary

**Successor to opencharly/plugin-deploy-pod#96**, auto-closed after five review rounds with every finding fixed in its commits; this PR carries that work unchanged. Nothing from #96's threads remains open.

A CDI GPU device forced every GPU deploy with a bind mount to run as **container root**: `podUserNSFor` returned `userns=host` with the workload as root, because crun cannot apply the CDI spec's FILE MOUNTS inside a keep-id user namespace (`mount_setattr /usr/bin/nvidia-cuda-mps-control: Operation not permitted`, exit 126). The mounts are the problem, not the device.

This change keeps the device and removes the mounts:

- **`cdi_spec.go`** reads the host's CDI spec — including the CDI **v0.7 top-level `containerEdits`**, where `nvidia-ctk` now puts the libraries, the env and the hooks (a per-device-only read sees the nodes and none of the mounts) — keeps the `deviceNodes` (top-level plus the `all` device's, deduped), drops `mounts` and `hooks`, and writes a devices-only spec to `<DataDir>/cdi/nvidia-devonly.yaml`. The directory is a runtime dependency of the generated unit, so it lives under the data root, not the cache.
- The spec's read-only **shared-object** mounts become read-only binds; its non-library mounts (the MPS binaries) are deliberately left out, since they are what fails first and no workload needs them.
- Because the derived spec drops hooks, the toolkit's `create-symlinks` hook is replaced by a bind for every host **SONAME** link that resolves to a mounted library (`libcuda.so.1`, `libnvidia-ml.so.1`, …). Without it the loader cannot find `libcuda.so.1` — measured, the container started and `CDLL("libcuda.so.1")` failed with "cannot open shared object file".
- The quadlet path passes `--cdi-spec-dir <dir>` (`QuadletConfig.PodmanArgs`) plus the binds (`ResolvedBindMount.ReadOnly`); the direct/systemd-unit path passes the same as engine arguments.
- **`userNSHostRoot` and `containerRootUser` are deleted**, with every call site (`engine_ops.go`, `resolve_f12.go`) and the now-dead `podCarriesCDIDevice`. A bind unit is keep-id as the image user, whichever device it carries.
- The sdk pin moves to `v0.2026328.2124`, the release that carries the two emitter inputs and the keep-id rule.

## Change classification

The `!` marker is correct: a GPU deploy with a bind mount changes from a container-root unit to a keep-id unit with a derived spec and library binds.

**Breaking change + rollback:** a GPU deploy with a bind mount is regenerated keep-id as the image user, with `--cdi-spec-dir` and the read-only library binds. Its unit stops carrying `User=0:0`; anything written by the old container as root is already the invoking host user's (`userns=host` rootless), so ownership does not change on disk. Rollback: revert and re-run `charly config` — the previous units regenerate byte-identically.
