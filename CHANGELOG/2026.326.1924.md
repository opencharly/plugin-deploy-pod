# 2026.326.1924 — fix(bed): the overlay builder bed ensures its base image too

## Summary

The overlay builder bed ensured only ONE of the two images its deploy needs. `overlay-builder-image-present` builds and asserts `overlay-npm-builder`, but the bed's subject (`pod-overlay-builder`) uses `overlay-base` as its image, and nothing built that. On a host where `overlay-base` had not been built, or had been cleaned since, the run died before rendering anything:

```
charly: error: command "deploy": deploy-dispatch add: deploy plugin: deploy-dispatch add:
prepare venue: InvokeProvider deploy:pod op=prepare-venue: rpc error: code = Unknown desc =
plugin-deploy-pod prepare-venue: overlay build: image not found in local storage: overlay-base
```

The check now builds and asserts BOTH images, so the bed is self-contained on a cold host instead of depending on an earlier run's leftovers.

The same edit **removes** the old `... | grep -q overlay-npm-builder || true` clause. That clause could not fail — `|| true` swallowed every outcome — so it asserted nothing; the `box inspect overlay-npm-builder` that follows it is the assertion that actually holds.

Found while re-running the bed on a newer charly binary for opencharly/charly#1231's evidence.
