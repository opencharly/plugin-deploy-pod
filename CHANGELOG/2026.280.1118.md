# 2026.280.1118 — fix(deps): bump sdk to v0.2026279.1734 — strip the retired system-layer version stamp

## Summary

Bump `candy/plugin-deploy-pod` to a post-fix `sdk`, and adopt the `spec` that
`sdk` now requires:

- `github.com/opencharly/sdk` `v0.2026273.207` → `v0.2026279.1734`
- `github.com/opencharly/spec` `v0.2026273.203` → `v0.2026276.0` (the transitive
  bump `go mod tidy` produced with the new `sdk`; `sdk`'s own `require`/`go.sum`
  moved it, so both `go.mod` and `go.sum` carry it)

Closes #28.

## Why

`deploy:pod` is served OUT-OF-PROCESS by this plugin, whose module pinned an sdk
from **before** the `loaderkit` fix in `sdk 0.2026275.1958`. That fix
(`readConfigStack` drops `retiredSystemDirectives` — the `version` key — from the
**system** layer before the merge, and skips a layer the strip leaves empty) is
what lets a host carrying the package-rendered, root-owned
`/etc/charly/charly.yml` resolve at all.

`spec` #183 removed the top-level `version` field from the closed `#NodeDoc`, so
without the strip the merged document resolves `version` as a NODE name whose
value must be a struct:

```
node "version": #NodeDoc.version: conflicting values "2026.261.1747" and {...}
                                  (mismatched types string and struct)
```

Because THIS plugin did the merge with a pre-fix sdk, every pod deploy aborted at
`config-setup` with the downstream symptom
`image not found in local storage: <deploy>:<calver>` — on any host carrying the
stale system stamp, regardless of the project. charly core and the sdk contract
already carry the strip; only this out-of-process consumer lagged.

## How tested — end-to-end, on the consumer bed

The change class is a Go-module dependency bump whose behaviour only manifests
through the plugin's actual `config-setup` path, so the proof is the CONSUMER
bed run against a fresh rebuild:

```
$ cat /etc/charly/charly.yml
version: 2026.261.1747                    # the retired stamp, PRESENT (unmodified host)

$ GOWORK=off go mod tidy && GOWORK=off go build ./... && GOWORK=off go test ./...
ok  github.com/opencharly/plugin-deploy-pod/candy/plugin-deploy-pod  0.170s

$ CHARLY_REPO_OVERRIDE="opencharly/plugin-deploy-pod=<this-worktree>" \
    charly check run check-dsh-pod
charly check run check-dsh-pod: PASS (steps=14)
```

`summary.yml` for the run: `14` steps, `failed: []`,
`errors: 0, warnings: 0, advisories: 0`. Before this bump the SAME bed aborts at
its `config` step (`image not found in local storage:
check-dsh-pod:check-dsh-pod-<calver>`); after it, `config` reaches
`config-setup` and the whole bed runs green. `CHARLY_REPO_OVERRIDE` is the
documented pre-merge local-override mechanism (`spec/proc/repo_override.go`), so
this is the real fix executed against a completely unmodified host.

The consumer leg (opencharly/pod-dsh#24) carries this `pod-dsh` bed as its gate
and is the second half of the B6 order.
