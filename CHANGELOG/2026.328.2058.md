# 2026.328.2058 — fix(config): write the deploy entry image before any other per-deploy overlay write

## Summary

`charly config` could not configure a deploy that was not already in the per-host config — a first deploy, a renamed deploy, a fresh host. It ran two writes in one pass: the port resolver created the overlay entry with `resolved_port:` alone (no `image:`), and the project-declared-volume write that followed re-read the file through `deploykit.SaveDeployConfig`'s degraded-load guard, which refuses to write a file holding an entry the loader cannot read:

```
charly: error: command "config": deploy:pod config: … persisting project-declared volumes:
refusing to write /home/atrawog/.config/charly/charly.yml — it holds 2 deploy entr(y|ies)
but only 1 load; this binary would erase the 1 a degraded load dropped
```

`image:` is mandatory on a pod deploy, so the entry the port step wrote could never load; every retry recreated it, and the deploy was permanently unconfigurable (opencharly/plugin-deploy-pod#93).

`image:` now goes **first**, in its own locked mutation (`ensureDeployEntryImage`), before ports, resource caps and project-declared volumes — every writer that can create the entry from nothing on a first-time config. It is a no-op when the entry already carries its image (the mutation reports no change, so nothing is written), and it heals an entry an older run left partial.
