# 2026.266.1057 — feat(deploy-pod): adopt spec 261 — retire the fleet vocabulary, read EngineName

## Summary

The schema-249→261 wave leg for the out-of-process `deploy:pod` target — a prerequisite for the engine-provider-class cutover (spec#144/#145). Without it a 261 `charly` cannot drive a pod bed: `plugin-deploy-pod` self-loads the project config via `loaderkit`, and its loader's `GateSchemaVersion` rejects a config NEWER than its own compiled spec HEAD (249), degrading the deploy key to the image name — the bogus `image not found in local storage: <key>:<key>-<calver>` symptom documented in `resolve_ref.go`.

- **fleet → deploy vocabulary (spec#137/CC-2).** `spec/fleet` is removed in spec 261; every removed identifier is swept: `spec.FleetNode`→`spec.DeployNode`, `deploykit.FleetConfig`→`deploykit.DeployConfig`, `FleetConfigMutator`→`DeployConfigMutator`, `MutateFleetConfig`→`MutateDeployConfig`, `SaveFleetConfig`→`SaveDeployConfig`, `LoadFleetConfig`→`LoadDeployConfig`, `ProjectFleetConfig`→`ProjectDeployConfig`, `MarshalFleetNode`→`MarshalDeployNode`, `loaderkit.BuildFleetNode`→`BuildDeployNode`, `loaderkit.LoadHostFleetConfigViaExecutor`→`LoadHostDeployConfigViaExecutor`, `spec/fleet.CandyMapKey`→`spec/deploy.CandyMapKey`, `dc.Fleet`→`dc.Deploy`, and the plugin-local `mutateFleet`/`saveFleet`/`saveFleetStub` identifiers + prose.
- **`#EngineName`.** `entry.Engine` is now the typed `spec.EngineName`; the two read sites convert explicitly (`string(entry.Engine)`), matching the sdk's own `deploykit/box_engine.go` / `deploy_file.go` reads.
- **Schema-head fixture.** `TestMigratedTreeStampAcceptedByEmbeddedParser` pinned the pre-wave 249 cap; it now asserts against the embedded `spec.SchemaVersion` (the module's HEAD), so it tracks every future bump instead of re-breaking.
- **Pins.** spec `v0.2026249.2129` → `v0.2026266.545`; sdk `v0.2026249.2114` → `v0.2026266.623`. The `go.sum` transitively refreshes `golang.org/x/{crypto,mod,net,sync,sys,term,text,tools}`; no require-set change beyond the two pins.
