## Summary

opencharly/sdk#544 made `SecretKeyForDep` **the** rule for a candy-declared secret's coordinate: an explicit
`key:` wins (everything before the LAST `/` is the service), otherwise the historical default
`(charly/secret, dep.Name)`. This repo carried the **third copy** of that rule — `secretKeyForDep` in
`secret_migration.go`, with the same LAST-slash split and the same default — used by the plaintext-env
migration and by the missing-secret report.

The copy is deleted (R5), all three call sites call `deploykit.SecretKeyForDep`, and the pin advances to the
tag that exports it:

**Every `go.mod` line the bump moves, accounted for** (`go mod tidy` after the pin):

```
- require github.com/opencharly/sdk v0.2026309.1926
+ require github.com/opencharly/sdk v0.2026320.617      ← the tag that exports the rule
- github.com/opencharly/spec v0.2026309.1917
+ github.com/opencharly/spec v0.2026320.16             ← the sdk's own contract-module dependency
+ cuelabs.dev/go/oci/ociregistry … // indirect          ← pulled by the newer spec
+ github.com/rogpeppe/go-internal … // indirect         ← pulled by the newer spec
+ golang.org/x/oauth2 … // indirect                     ← pulled by the newer spec
+ golang.org/x/sync … // indirect                       ← pulled by the newer spec
```

So this is **not** "no new dependency": the sdk bump carries its contract-module bump, which brings four
indirect modules into the build graph. They are pinned to the versions the sdk/spec tags themselves resolve
(`go.sum` records their hashes), and none of them adds a build script or a new direct import here.

Behaviour is identical — the two implementations agreed on every declaration the build-time validator
accepts — so what changes is that the coordinate now has ONE implementation in the org. That is the
prerequisite for opencharly/pod-openwebui#19's per-deploy decision: one place to move instead of three.
The doc comments that named `secretKeyForDep` now name the shared rule.
