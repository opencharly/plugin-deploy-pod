# 2026.241.2129 — fix: bump sdk to v0.2026241.2117 for the machine-venue home-token fix

## Summary

Bumps `github.com/opencharly/sdk` to `v0.2026241.2117` (with the `spec` bump `go mod tidy`
pulls in) to deliver the machine-venue `{{.Home}}`-token fix to **pod deploys**.

This plugin walks deploy plans through `kit.WalkPlans`. Until sdk v0.2026241.2117 that walk
never resolved the deferred `{{.Home}}` token on a machine venue, so a candy's
home-relative `copy: to: ${HOME}/...` reached `PutFile` carrying the literal token and
landed in a directory named `{{.Home}}` in the venue home — silently, with no error,
while `mkdir:`, `write:` and `command:` from the same candy applied normally (those legs
render shell that expands `$HOME` on the venue).

The fix itself is opencharly/sdk#188. **A plugin is built against its own pinned sdk**, so
each plan-walking plugin has to repin for its venue to get the fix — this one covers
overlay candies applied onto a running pod. Diff is `go.mod` + `go.sum` only.

Refs opencharly/charly#460.

## How tested

**Module gates on the committed tree:**

```
$ GOWORK=off go build ./...   ok
$ GOWORK=off go test ./...    ok
```

**The delivered behaviour is live-proven**, on the sibling venue where a disposable bed can
exercise it without touching a real machine. A minimal candy — one `mkdir:`, one `copy:`,
one `write:` into the same directory — applied to a disposable Arch cloud-image VM bed:

*Before* the sdk bump:

```
FAIL  the copied file landed alongside the written one  [copyrepro-copy-landed]  exit=1
$ sudo find / -xdev -name copied.txt
/home/arch/{{.Home}}/copyprobe/copied.txt      # the literal token became a directory
```

*After*, full `charly check run` including the fresh-rebuild leg:

```
3 steps: 3 passed, 0 failed, 0 skipped   EXIT=0
PASS  the copied file landed alongside the written one  [copyrepro-copy-landed]  exit=0
```

**Why the proof is on that venue and not this one:** the code delivered by this bump is
byte-identical (the same `kit.WalkPlans`), and exercising *this* plugin's venue means
deploying onto a real host/pod rather than a disposable guest. Running a `target: local`
deploy against the operator's own workstation to demonstrate a dependency bump would be a
destructive test for no additional information, so the shared seam is proven where it can
be proven safely.
