# 2026.308.1638 — fix(pod): resolve the deploy key to a box name before prepare-venue/rebuild

## Summary

**Head `48c99de9ad94eb938f921621ddf1dc845f9b9dbd` (tree `6cc21e9d0dbf879060294c7a81a2a1c21dd14687`), base `1f322ea` — 6 files, +376/−155. Four commits.**

A qualified pod bed is dispatched as `ns/name` (the deploy **key**), while its box is the declared `image:`. This PR makes the whole path — prepare-venue/rebuild, config, and start — resolve that key to the **box**, and then to the **image ref the build actually produced**.

| file | what it does |
|---|---|
| `resolve_ref.go` | **`resolveBaseBoxName` / `resolveDeployBoxNameForKey`** — ONE deploy-key→box rule: per-host overlay entry first, then the project config in both spellings (`ns/name` exact key, `ns.name` project key); an explicit `p.Image` passes through untouched; the key is returned only when genuinely unresolvable. **`resolveDeployImageRef` / `projectBoxRegistry`** — ONE box→image-ref rule, applied BEFORE ensure-image/ExtractMetadata: the box's own `registry:`, else its NAMESPACE's `defaults.registry`, then the box LEAF (the same rule the host build path applies). The post-hoc, image-label-sourced qualifier is deleted. |
| `lifecycle.go` | `podPrepareVenue` resolves **before** `HostBuild("overlay")` and passes the resolved name as `OverlayBuildRequest.Image`, keeping `DeployName` as the deploy key; `podRebuild` uses the same helper |
| `config_setup.go` | the `charly config` path resolves through the same helper; no second qualification after the existence check |
| `resolve.go` | the start path drops the redundant re-resolve keyed on the image's OCI registry label |
| `resolve_box_name_test.go` | the key→box regression plus the new ref regression (both box spellings) |
| `resolve_ref_test.go` | the deleted qualifier's test removed with it (R5) |

The ordering matters and is the substance of the third commit: the host's overlay builder takes `req.Image` as the base ref, so resolving *after* the `HostBuild` call was one step too late.

### Round 4 finding — the config path composed a bare box address as an image repo (blocking, fixed here)

The image the build produced is `ghcr.io/opencharly/check-k8s-deploy-app:charly.check-sidecar-pod-2026.307.2336` (from the bed's own `check-image.log`, and confirmed present by `charly box list tags`; its `ai.opencharly.registry=ghcr.io/opencharly` label is read by `charly box labels`). The config path asked for the namespace-qualified **box address** with **no registry**.

- **Mechanism.** `resolveDeployRefLocal` composed the ref with `kit.ResolveShellImageRef("", deployBoxName, tag)` — a literal empty registry. `deployBoxName` on this path is the deploy's resolved box address (`charly.check-k8s-deploy-app`, persisted in the per-host `image:` by deploy-add, or the project deploy map's bare leaf). The registry qualification that existed ran 57 lines later in `runConfig`, AFTER `ensureImagePresent`/`ExtractMetadata`, and read the registry from the IMAGE's OCI label — unreachable precisely because the unqualified ref fails the existence check first.
- **Missed control.** The existing regression test asserted the box NAME (`check-k8s-deploy-app`) but not the IMAGE REF, and accepted `check-k8s-deploy-app:testtag` as the expected ref. That expectation encoded the bare-ref bug, so the test was green over the defect. Nothing in the pre-push gate tied the resolver's ref to the project's `defaults.registry`.
- **Blast radius.** Every qualified pod deploy whose box lives in a namespace with a `defaults.registry` — the config and start paths both. The prior start-path re-resolve was a second, label-sourced rule and is removed with it.
- **Root fix.** Compose the ref ONCE, before any existence check, from the project's (box registry → namespace defaults.registry, box LEAF), using the same `spec` primitives as the host build path. The regression test now asserts the full ref for both box spellings, and a disabled `FindBoxByLeaf` fallback fails it.
- **Classification: blocking** — this PR's R10 gate is red because of it, and its claim is false without the fix. Fixed here, not filed.
- **Pre-existing, with evidence.** The empty-registry composition is unchanged from `origin/main`: `git show origin/main:candy/plugin-deploy-pod/resolve_ref.go` line 57 is `kit.ResolveShellImageRef("", deployBoxName, tag)`, and the post-hoc qualifier is at `config_setup.go:257` on main. It was masked because on main the bed died earlier, at deploy-add (`unknown box "charly/check-sidecar-pod"`, plugin-build#46); this branch fixed that, so the bed reached config and the pre-existing composition surfaced with a different bare name.
