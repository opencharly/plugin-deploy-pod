# 2026.269.1234 — fix(deploy-pod): adopt the namespace-aware sdk/spec pins (RCA-H)

## Summary of changes

Adopt the namespace-aware `sdk`/`spec` contract pins in the out-of-process
`deploy:pod` plugin, and add the R7 regression test that proves it.

### RCA (8-step, measured live)

**Unexpected.** From the umbrella root, `charly check run charly.check-dsh-pod`
(a namespaced pod bed) passed `image-build` + `check-image` + `deploy-add`, then
failed at `config`:

```
charly: error: command "config": deploy:pod config: InvokeProvider deploy:pod
op=config-setup: rpc error: code = Unknown desc = image not found in local
storage: charly.check-dsh-pod:charly.check-dsh-pod-2026.269.1115
```

`deploy add` had built and tagged the real artifact
(`ghcr.io/opencharly/dsh-app:<run-tag>`), but `config` sought the **dotted
deploy name** as an OCI ref — a reference nothing ever built.

**Mechanism.** `config` resolves the image via `resolveDeployRefLocal` →
`deployKeyToBoxLocal`. On an empty per-host overlay that resolver's only
remaining source is the project fallback:

```go
pc := deploykit.ProjectDeployConfig(uf)
if e, ok := pc.Deploy[box]; ok && e.Image != "" { return e.Image }
return ""   // → the deploy key becomes the box name
```

This plugin pinned `sdk v0.2026266.623`, whose `ProjectDeployConfig` projected
the root-scope `uf.Deploy` map only. A namespaced bed lives in an imported
namespace, so `pc.Deploy["charly.check-dsh-pod"]` was **absent**: the box name
degraded to the deploy key, and `config` fell through to
`ResolveShellImageRef("", "charly.check-dsh-pod", tag)` →
`charly.check-dsh-pod:<tag>` — the `image not found in local storage` failure.

**Root cause.** The producer/consumer split from sdk#297 / spec#164: the
namespace-aware `UnifiedFile.Deploys()` fold (spec) and the `ProjectDeployConfig`
projection of it (sdk) landed, but this out-of-process consumer was never
re-pinned, so it kept projecting the root-only map.

**Missed control.** The plugin's pins are independent of charly's, so a
contract-module namespace cutover must bump every out-of-process consumer.

**Blast radius.** Every namespaced pod deploy / pod check bed resolved through
this plugin's project fallback (the whole `charly.*` pod-bed set in the roster).

### Fix

Bump the plugin's contract pins to the merged namespace-aware releases:

- `github.com/opencharly/sdk v0.2026266.623 → v0.2026269.920`
- `github.com/opencharly/spec v0.2026266.545 → v0.2026269.212`

`ProjectDeployConfig` now folds `uf.Deploys()` (local bare + `ns.name`,
recursive), so the qualified key resolves to its **leaf** box name
(`dsh-app`) — the same OCI artifact `deploy add` built.
