# 2026.327.1741 — fix(rebuild)!: a pod deploy that lives in the HOST config is updated, not re-added from the project

## Summary

`charly update <deploy>` was unusable on any **pod deploy the operator created in the HOST config** (`charly config <image>`, `deploy add <name> <ref>`). The rebuild sequence's first leg is `deploy add <name>` with no `<ref>`, which resolves the deploy from the **project's** `charly.yml` — and a host-config deploy has no project entry:

```
$ charly update strata
charly: error: command "deploy": charly deploy add: no <ref> and charly.yml has no entry for "strata"
```

while `charly deploy show strata` resolved the same deploy — the tool contradicted itself (opencharly/charly#1249).

**The fix:** that leg is the PROJECT route and exists for a FRESH deploy. Rebuilding an EXISTING deploy does not need it — the `config` leg re-renders the quadlet from the host entry, which is what re-resolves the image. The leg now runs only when the host has **no** entry for the key (`podRebuildHasHostEntry`), and an **unreadable** config is never read as "no entry", because that would silently skip a fresh deploy's registration.
