# 2026.288.0723 — fix(pod)!: the image-ensure path takes the RUN engine, and the peer request drops the retired field (opencharly/opencharly#481 leg 17)

## Summary

**Leg 17 of `opencharly/opencharly#481`, the last of the five consumer lanes: `plugin-deploy-pod` migrates the engine the pod deploy hands to its image-ensure path, and the peer request it sends.**

`ensureImagePresent` guarantees a pod's image is in podman's store before the config is written. It read **`rt.BuildEngine` — the IMAGE BUILDER** — which was wrong on both counts once the builder became BuildKit: the field is **gone from the contract** (spec leg 1), and **a builder is not a container engine**, so it could never name a store that *holds a container image*. That is exactly what this path asks an engine to be — transfer the image to podman, or ensure it through the `build:ensure` peer — so the answer was always **`engine.run`**.

**This is the operator's scope's own predicted case — a REPOINT, not a retirement** (`engine.build` has no successor; this consumer's need does, and it was always the run engine's job). The four call sites now pass `rt.RunEngine`, and the parameter plus its commentary are renamed with it, because a value called `buildEngine` while it holds a run engine is precisely the confusion this lane's scope warns about — the word "builder" carries three meanings in this tree and only one is the subject.

The peer request loses the contracted-away field, and its value is deliberately **not** replaced by another field (the request already carries `RunEngine`, which is what the receiving word uses):

```go
-	params, err := json.Marshal(spec.BuildEnsureRequest{
-		Image:       imageRef,
-		BuildEngine: buildEngine,
-		RunEngine:   podRunEngine,
-	})
+	params, err := json.Marshal(spec.BuildEnsureRequest{
+		Image:     imageRef,
+		RunEngine: podRunEngine,
+	})
```

**Also in this commit:** this repo's **own `disposable: true` class-gate bed** (it had none — the root `charly.yml` was `discover:` and nothing else), the **five** R5 **stale-name corrections** in the existing test (~15, ~47, ~50, ~59, ~68 — the header comment, the inline note in the cross-engine stub, the two check-order comments and the assertion's error message), whose wording still called the run engine a build engine, and `.gitignore` coverage for the bed's generated evidence.
