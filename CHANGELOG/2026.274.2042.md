# 2026.274.2042 — fix(deps)!: adopt spec v0.2026273.203 + sdk v0.2026273.207 (schema-gate fix)

## Summary

Bump `spec`/`sdk` past the schema gate that was degrading every `deploy:pod` bed's deploy key, and
adopt the two API moves the bump brings. Fixes the producer leg of `opencharly/plugin-deploy-pod#17`.

## RCA

Every `deploy:pod` bed fails at its `config` step:

```
image not found in local storage: <bed-key>:<bed-key>-<calver>
```

(the built image is `ghcr.io/opencharly/<image>:<bed-key>-<calver>`, but the loader asks for
`<bed-key>:<bed-key>-<calver>` — the deploy key degraded to the image NAME).

Root cause: this plugin self-loads the project config, and it was compiled against spec
`v0.2026269.212` while the config is at spec >= 270 — the load-time schema gate rejected the newer
config and degraded the key. The plugin's own CHANGELOG documents this exact class
(`CHANGELOG/2026.266.1057.md`). This is the `charly#733` schema-versioning cutover reaching this
repo: the gate is being retired, and a stale build must be re-pinned.

## Change

| item | from | to |
|---|---|---|
| `github.com/opencharly/spec` | `v0.2026269.212` | `v0.2026273.203` |
| `github.com/opencharly/sdk` | `v0.2026269.920` | `v0.2026273.207` |

Two API adaptations the bump requires (the sdk#288 ctx threading + a type move):

- **ctx threading:** `deploykit.SaveDeployConfig` / `MutateDeployConfig` / `SaveDeployState` now
  take a trailing `context.Context` — passed the `ctx` already in scope at each call site.
- **type move:** `spec.BuildRequest.ExtraCandyRefs` is now `[]spec.ExtraCandyRef` (was `[]string`);
  the overlay refs are mapped at the request site.
- **R5 sweep:** `TestMigratedTreeStampAcceptedByEmbeddedParser` asserted the now-DELETED
  `loaderkit.GateSchemaVersion`/`spec.SchemaVersion` (the schema-versioning removal) — deleted.
