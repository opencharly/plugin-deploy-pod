# 2026.242.0932 — chore(deps): repin sdk to v0.2026242.913 for the overlay user reset

## Summary

Repins the sdk so the overlay user-state fix actually reaches deployments:

```
github.com/opencharly/sdk v0.2026242.11 => v0.2026242.913
```

`opencharly/sdk#192` fixes a user-state leak between overlay candies. `OCITarget.emitPlan` splices each step's Containerfile fragment verbatim, so a candy whose fragment legitimately switches to the image user left every **later** candy's root work running unprivileged — surfacing as `opencharly/charly#467`, `pacman-key --init` failing with *"pacman-key needs to be run as root for this operation"* partway through an overlay build.

This plugin is the component that assembles overlay Containerfiles, and it builds against its **own** pinned sdk. Until this repin lands and is tagged, the merged sdk fix changes nothing for any venue — which is the point of the bump.

**What proves the behaviour is in sdk#192, not here.** That PR reproduced charly#467 live — an overlay executing `USER root` (step 2), `USER 1000` spliced from a plugin fragment (step 8), then `pacman-key --init` at step 11 with no reset in between — and showed that adding the single `USER root` the fix emits takes the identical Containerfile from `exit=1` to `exit=0, Successfully tagged`. It also carries the unit guards and a negative control that fails without the reset. This PR changes no code of its own; it moves the pin that gates delivery, and the diff is `go.mod` + `go.sum` only.
