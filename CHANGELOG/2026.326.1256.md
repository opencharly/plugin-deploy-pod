# 2026.326.1256 — test(overlay): the artifacts call has its own test, through the Generator's resolver seam

## Summary

A pod overlay now renders its candies' builders the way the box build does (opencharly/sdk#608).

- `buildOverlay` emits the overlay candies' builder stages through the SAME `Generator` path the image build uses (`EmitBuilderStages`), hoisted BEFORE the main `FROM`, and copies each builder's payload in after it (`EmitBuilderArtifacts`). A builder stage opened mid-file used to make the builder the final image and copy nothing back.
- Each builder image the stages name is ensured FIRST, through the plugin's own `build:ensure` dispatch, because an ensure that builds regenerates the project's `.build/` tree and prunes every non-box directory — the overlay dir included (measured: the Containerfile write then failed ENOENT).
- The Containerfile layout is one pure function, `overlayMainStage`, so the order is testable.
- The ensure-first ordering is one function, `prepareOverlayBuild`, and `TestPrepareOverlayBuildEnsuresBuilderImagesBeforeCreatingTheDir` drives it with a stub `build:ensure`: every needed builder image is ensured, the overlay dir does NOT exist at the moment each ensure runs (the `.build` prune that motivated the ordering), a failed ensure stops the build, and the dir is created after. Deleting the loop fails it.
- The builder wiring is one function, `emitOverlayBuilders`, which drives the Generator the image build uses. `TestEmitOverlayBuildersDrivesTheGeneratorsBuilderPath` refuses a needed builder with no resolved stage — an outcome only the real `EmitBuilderStages` call produces — so removing the two builder calls together fails it, not just the layout helper. The artifacts half has its own test: `TestEmitOverlayBuildersEmitsThePayloadCopyWhenAStageResolves` stubs the Generator's `ResolveDetectionBuilderStage` seam (the same one sdk's own tests use) with a reply carrying a stage and a `COPY`, declares the builder externalized as the host does, and requires both halves — so deleting only the `EmitBuilderArtifacts` call fails it.

**The overlay builder path now has a live bed** (opencharly/plugin-deploy-pod#68): `check-overlay-builder` builds a base box and an `overlay-npm-builder` box locally from `docker.io/library/fedora:43` (no registry auth, because #65 blocks published images), deploys a disposable pod whose `add_candy` needs the npm builder, asserts the rendered Containerfile has the builder stage BEFORE the main `FROM` and the payload `COPY` after it, asserts the overlay image was built, and removes the deploy. Measured on this host: the render is `FROM … AS …-npm-build` (line 7), `FROM localhost/overlay-base:…` (line 18), `COPY --from=…-npm-build …` (line 23), the deploy reports `Overlay image ready`, and the bed is 3 of 3 steps PASS.

Two candies are new files in this diff: `candy/npm-toolchain` (the producing candy that installs node/npm on the fedora base, with a build-context check) and `candy/overlay-builder-probe` (`charly.yml` + `package.json`, the fixture whose manifest makes an image need the npm builder). They exist so the bed can compose a builder box and a builder-needing candy entirely from local builds.
