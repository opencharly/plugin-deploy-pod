# 2026.331.1823 — fix(bed): `charly update --build` rebuilds a box, or refuses and says nothing was built

## Summary

`charly update <name> --build` promises "rebuilds the artifact first". On this host it built nothing and
reported success: `rc=0`, no build line, and the container was recreated on the OLD image
(`opencharly/charly#1297`). Two independent causes, both fixed.

**1. The flag never arrived.** The host marshals `spec.DeployTargetRebuildOpts` as
`rebuild_image` / `dry_run` / `tag`; `podRebuild` decoded it into a hand-rolled struct declaring
`RebuildImage` / `DryRun` / `Tag` with **no json tags**. `rebuild_image` does not match `RebuildImage` (the discriminator test below asserts both directions),
so the flag decoded to **false** and the build leg never ran — silently, because every other leg
succeeded and the command exited 0 (the discriminator test below asserts both directions). `tag` matched case-insensitively, which is exactly why `--tag` kept
working and hid the mismatch. The decode now uses `spec.DeployTargetRebuildOpts` itself: one wire shape,
no second struct to drift (R2).

**2. When it does arrive, the name is not a box.** The build leg fed the deploy's recorded **image** ref
to `box build` — `ghcr.io/opencharly/whisper:2026.325.2318` → `import namespace "ghcr" not found`, or a
silent no-op. A deploy entry records an image, never a box (there is no `box:` field). `rebuild_box.go`
now resolves the box from what the deploy and its project already declare, in the order they can be
trusted:

1. the recorded image, when it is a **bare name** the project declares as a box (`image: whisper`,
   `image: comfyui-cdi` — the bed shapes);
2. the **deploy key's base** name, when the project declares a box by it (`whisper` → `box/whisper`, the
   owner-repo shape the CDI boxes moved to);
3. otherwise a **refusal before anything runs**, naming the recorded ref, the names it looked for, and
   the remedy — a redeploy on the existing image must never look like a rebuild.

No ref parsing on purpose: the box never has to be derived from a registry ref, because the deploy key
and the bare-image form already carry it, and a locally re-implemented strip-registry/tag rule would
duplicate deploykit's own (R2). The project is read the same way `deployKeyToBoxLocal` reads it — box
name → `projectConnect` → **dir** → unified loader — which is the leg that made the first attempt refuse
a legitimate rebuild.

```

```

A box with an empty `plan:` cannot pass `check box`, so the documented build→check→restart sequence
stops there for such a box regardless of `--build`. The tracker is `opencharly/plugin-check#110`; it is
not this diff's subject and it does not make the rebuild silent — the build ran, which is the change.

**The four tests, including the change's own discriminator:**

- `TestPodRebuildOpts_DecodeTheHostWireShape` — marshals the canonical opts and asserts
  `rebuild_image` survives; then asserts the **retired** camel-only struct does NOT read that key. If
  that second assertion ever passes, the discriminator is dead and the silent skip is back.
- `TestRebuildBoxCandidate_BareImageNameBeatsTheKey` — a bed's key (`check-whisper-pod`) with a bare
  recorded image (`whisper`) chooses the image's box; a fully-qualified ref falls through to the key;
  neither declared ⇒ no candidate (never a guessed name).
- `TestResolveRebuildBoxName_DeclaredBox` / `_InstanceQualifiedKeyUsesTheBase` — the IO wrapper resolves
  through a declared box, and a `base/instance` key uses the base.
- `TestResolveRebuildBoxName_UndeclaredBoxRefuses` / `_ProjectFaultIsNamed` — the refusal names what was
  not built and the remedy, and a project-load fault is named rather than read as "no box declared".

### Spike

R12's spike round, tabulated — three candidates for "what should `--build` do when the deploy names no
box":

| candidate | instrument | result |
|---|---|---|
| A — resolve the box from the names the deploy + project DECLARE (recorded bare image, then key base), refuse otherwise | the two live arms + the candidate unit test | **wins**: builds for both real shapes (`overlay-base` bare image; `whisper` key==box) and refuses loudly otherwise |
| B — fix the unknown-name path instead, making `box build <ref>` error (plugin-box) | `charly box build ghcr.io/opencharly/whisper:…` → rc=1 `import namespace "ghcr" not found` | rejected: loud, but it changes another repo's verb and still leaves `--build` unable to build the deploys that need it |
| C — refuse only, never resolve | arm 1 alone | rejected as insufficient: five of six CDI deploys record refs the refusal would reject when the project does declare the box |
| D — derive the leaf from the registry ref | reading `deploykit.repoLeaf` (unexported) | rejected: it would duplicate a rule that already exists, for a name the deploy key or the bare image already supplies (R2) |

The winning candidate's success is the proof the RCA was right: with the flag decoded and the box
resolved, `--- Building overlay-base ---` appears where the pre-change run produced zero build lines.
