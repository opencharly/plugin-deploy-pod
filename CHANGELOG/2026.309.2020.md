# 2026.309.2020 — fix(pod): honor a deploy's authored engine selector in config, start and teardown

## Summary

This is the `deploy:pod` leg of opencharly/charly#1109. Four defects in one
coherent change:

1. **The authored selector was never persisted.** `PrepareVenue` shipped a
   state patch containing only `resolved_image`, so a `pod:` node authored
   `engine: containerd` produced a per-host entry with no `engine`, and
   `charly config` fell back to the host-wide `engine.run` (podman). The patch
   now carries the node's `Engine`, plus its box name and the `pod` target so
   an engine-only no-overlay entry is a complete image-backed pod entry (and
   never the targetless `group:` the node-form writer would otherwise emit).
2. **The run mode came from the wrong engine.** `config`/`start`/`remove`
   branched on `rt.RunMode`, resolved for `rt.RunEngine` (the host-wide
   `engine.run`). `runtimeForSelection` re-derives the mode from the SELECTED
   engine's capability row (`container.EngineRunModeFor` via
   `kit.DetectRunMode`), so a containerd deploy emits and starts the engine's
   `systemd-unit` (`nerdctl run`), never a podman quadlet. `direct` is
   engine-agnostic and is preserved.
3. **A locally-built bed image could not reach the containerd store.**
   `build:ensure` received no project context, so the local build fallback
   failed `buildkitdrive: build: no context`. `ensureImagePresent` now threads
   the project dir (through the existing `deploy-plugins-connect` preamble)
   into the `build:ensure` request.
4. **The emitted host unit CHDIR'd to the container's workdir.** The first live
   containerd start failed `status=200/CHDIR`: `writeSystemdUnitConfig` passed
   the CONTAINER working dir (`/home/user`) as the engine unit's
   `WorkingDirectory=`, which systemd applies on the HOST. The container workdir
   is already the engine argv's `run -w <path>`; the host unit now omits it.

Adopts `spec v0.2026309.1917` and `sdk v0.2026309.1926` (producer-first:
opencharly/spec#292, opencharly/sdk#487). The `plugin-build` producer legs the
live proof needed — local build into the requested run engine, aliasing the
build's own produced ref, and keeping a handled pull miss out of the gate log —
are opencharly/plugin-build#52. The charly pin bump follows the tags.

### The measured venue blocker (not a finding in this diff)

The container did **not** start on this host, and this PR does not claim it
did. Two pre-existing venue/contract defects block it, both filed and
separable:

- **`crun` is not registered on this host's containerd.** The containerd
  start-plan names `crun`; the unit fails `failed to resolve runtime path:
  invalid runtime name crun`. The same base image runs with the default,
  `runc`, and `io.containerd.runc.v2` (`rc=0` each) and fails with `crun`
  (`rc=1`). Filed as opencharly/plugin-containerd#16. `crun` is not installed
  (`command -v crun` is empty); it is the containerd lease guest's runtime, not
  this desktop's.
- **A typical charly image's `ai.opencharly.description` label is over
  containerd's 4096-byte container-label cap** (measured: `pod-crabbox` 4710,
  `check-k8s-deploy-app` 6062, the probe image 9815). Filed as
  opencharly/spec#293. A minimal proof image (100-byte label) removes this
  variable and reaches the `crun` failure, which is how the two were separated.

The bed also surfaced two cleanup/readiness gaps, both filed:
opencharly/plugin-pod#27 (`charly remove` leaves the containerd container, so
the next start fails `name-store`) and opencharly/plugin-check#142
(`wait-ready` probes the host engine, not the deploy's, a vacuous 90 s wait).

Tier: **`analysed on a live system`** — the changed runtime path ran live with
retained output; the full bed did not pass because of the venue's missing
`crun` handler, not because of this diff.

## Change classification

Behavior change at the pod deploy boundary: a per-deploy engine selector now
persists and drives unit emission, start/stop and config removal; an
engine-only state patch is classified as `pod`; `build:ensure` receives the
project dir; the host unit no longer carries the container workdir. No authored
key changes spelling and no migration is owed. Rollback: revert this PR and the
adopted tags; a deploy without a selector behaves exactly as before.

**Breaking change + rollback:** none — a deploy with no per-host engine keeps
the previous host-wide resolution, and the new state-patch fields are optional.
