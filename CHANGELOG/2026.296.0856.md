## Summary

`pod-charly-automation` is a skills-only carrier (0 `.go`, 0 `.cue`, no candy directory). The
sidecar model's implementation is **this** candy — `sidecar_resolve.go` (resolve/merge),
`sidecar_embedded.go` (the embedded template library) and the `charly config --sidecar`
attachment — which the skill's own `## Source` section names. `plugin-sidecar` was the tempting
wrong home: it only decodes the `sidecar:` entity (`kind:sidecar`), the same shim-vs-substance
distinction that moved `egress` to `plugin-egress` in opencharly#611.

never from its name; then where that entity exists; then the negative control.

**Two things this body deliberately does NOT claim, because they are worth stating.**

- **A duplicate exists for now, and the generator tolerates it.** The carrier still
  declares the same `(kind, family, name)`; `plugin-marketplace`'s `preferEntity`
  (`resolve.go`) dedupes on exactly that triple, so one page is published — currently the

  states one (`spec#247`), which is why `<name>-skill:` keys and the `name:` field can
  differ without consequence.

**Producer-first.** No carrier loses a node here: those removals and retirements belong
to the session that claimed the carriers (opencharly/opencharly#600).
