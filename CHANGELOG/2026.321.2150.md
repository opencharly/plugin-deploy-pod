## The measurement that changed the task

The issue (and my brief for it) said the fix was the `type:secret` owner's `bind` returning an `#Opaque` handle. **A spike measured that the wire describes a mechanism with no host side:**

```console
== [1] host-side provider .Bind( call sites in charly+sdk (non-test) ==
rc=1 lines=0

== [2] the closed provider-class vocabulary ==
655:#ProviderClassNames: ["kind", "deploy", "verb", "step", "build", "builder", "command", "engine",
    "workflow", "loader", "refs", "agent-runtime", "terminal"]

== [3] the gatherer provide surfaces ==
56:	"env": {collect: func(candy spec.Candy) []needsolver.Provide {
```

- **`type` is not in `#ProviderClassNames`** — a `providers: [- type:secret]` entry is refused by the closed vocabulary.
- **Zero** `.Bind(` / `BindRequest{` call sites in `charly` or `sdk`: **core never calls a provider's `bind`**, so no handle could ever be minted into state. The proto RPCs and `#BindInput`/`#BindOutput` exist (`spec/proto/plugin.proto:448`, `spec/schema/bind.cue:40-53`) — **the transport exists, the dispatch does not.**
- The wire has **no resolve-to-bytes leg** either.

**So building the handle owner would have added five repos of indirection for zero change in delivered bytes.** The spike said so before anything was written, which is what RDD is for.

## And the actual leak, measured on the rendered artifact

**The first measurement was a throwaway probe, not the committed test.** It rendered the unit BEFORE the fix, through a scratch harness, and produced:

```
Secret=charly-seam-proof-box-seam-proof-token,type=env,target=SEAM_PROOF_TOKEN
Environment=SEAM_PROOF_TOKEN=p75-state-leak-probe-9f2c
```

**That is not a red-first and this PR does not claim it as one** — a red-first is the committed test failing, and §R7 below quotes the real one (a plant that restores the pair shape, failing three tests). **A probe that is thrown away must be labelled as thrown away**; presenting it under the committed test's name was the defect the review caught.

**The unit carried both.** The `Secret=` line is the handle-shaped delivery that already worked (label → `CollectCandySecretAccepts` → `ProvisionPodmanSecrets` → `quadlet.go:188`). The `Environment=` line was #76's `PodEnvVarsWithSecrets` — **a second copy of the same delivery whose only effect was to persist the value.**

> **A duplicate delivery is not a redundancy; here it was the leak.**

## The change

| file | what changed |
|---|---|
| `candy/plugin-deploy-pod/config_secret_env.go` | **two changes, both in the diff:** `PodEnvVarsWithSecrets` → `EnsureBoxChainSecrets` (returns **names**, never values, so a caller has nothing it could write into state); and `scopedCandySecrets` → **`ensureBoxChainSecrets`**, its return narrowed from `map[string]string` to **`[]string`** — the identifier AND the signature. **The narrowing IS the fix**: a function returning a map of pairs has somewhere to put a value, and this one did. | `candy/plugin-deploy-pod/config_setup.go` | the ensure now runs **before** `resolvePodProvisionSecrets`, so a value minted on the first `charly config` is the one provisioned; **nothing touches `envVars`**. |

| `candy/plugin-deploy-pod/config_secret_env_test.go` | updated for the narrowed return shape; the cycle-termination and scoping cases kept |

**The signature is the fix.** A function that returns `[]string` of names cannot leak a value; a function that returns `map[string]string` of pairs can, and did.
